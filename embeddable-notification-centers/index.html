Embeddable notification centers

The notification center, or “inbox”, is the bell and the message list a product shows its users. This page compares those of five vendors on four criteria, based on their official documentation collected on November 4, 2026. Vendors are presented in alphabetical order; the list is not exhaustive, and none pays to be on it.

Depending on your need

This site does not name a winner: the right tool depends on what you are looking for. The rows to read first:

A bell fully matching your brand
“Notification center: custom UI”, “Notification center: platforms”.
Let each user choose what they receive
“Notification center: preferences”.
Make sure users read only their own notifications
“Notification center: user authentication”.

Platforms

Where the component is displayed: web, mobile, and with which frameworks.

Courier
Client SDKs render the in-app interface in React, Vue, iOS, Android and Flutter. (source, November 4, 2026)
Knock
In-app SDKs for React, JavaScript (outside React), React Native, Swift (iOS, macOS), Kotlin (Android) and Flutter. (source, November 4, 2026)
MagicBell
A ready-to-use inbox for React, Svelte and Preact. (source, November 4, 2026)
Novu
Client SDKs for React and React Native, and a headless client for custom interfaces. (source, November 4, 2026)
SuprSend
Inbox for React, JavaScript (Angular, Vue…) and React Native; iOS and Flutter in headless mode. (source, November 4, 2026)

Custom UI

When the interface provided is not enough: what the vendor gives you to build your own.

Courier
Replace parts of the inbox with your own renderers (web SDK only), or build the whole interface, on every platform, from the SDK’s messages, counts and actions. (source, November 4, 2026)
Knock
React hooks to build a fully custom interface, backed by Knock’s feed API and real-time service. (source, November 4, 2026)
MagicBell
Styling through CSS variables, replaceable components and a free-form layout. (source, November 4, 2026)
Novu
React hooks (useNotifications, useCounts…): you handle layout and styling, Novu provides notification state, real-time updates and actions. (source, November 4, 2026)
SuprSend
React hooks and context providers to build your own feed, with full control over styling and layout. (source, November 4, 2026)

Preferences

What the vendor provides so that the user chooses what they receive, and on which channel.

Courier
An embeddable preferences component: the signed-in user chooses which topics they receive and the channel for each. (source, November 4, 2026)
Knock
A guide to building a complete preference center with React and Knock’s preferences API. (source, November 4, 2026)
MagicBell
A UserPreferences component: the user turns each channel on or off, category by category. (source, November 4, 2026)
Novu
A Preferences view built into the Inbox: the subscriber sets their channels for all workflows or workflow by workflow. (source, November 4, 2026)
SuprSend
A ready-to-embed preferences page, synced with the categories defined in the dashboard, and hooks for a custom interface. (source, November 4, 2026)

User authentication

The browser requests a user’s notifications. Having your server sign their identity prevents a third party from reading someone else’s notifications by impersonating them. What each vendor provides:

Courier
Client SDKs authenticate with a short-lived, limited-scope JWT that your server issues with your API key. (source, November 4, 2026)
Knock
With enhanced security mode, the client must present a user token signed by your server; without this mode, the user’s identifier is enough. (source, November 4, 2026)
MagicBell
The user authenticates with a JWT that your server generates with the project’s secret key, which must never appear in the browser. (source, November 4, 2026)
Novu
HMAC encryption, to be enabled before going to production, signs each subscriber identifier with a secret key; Novu checks this signature on every feed request. (source, November 4, 2026)
SuprSend
Enhanced security mode, recommended in production, requires a user token (JWT) signed by your server; SuprSend considers the public key alone insufficient in production. (source, November 4, 2026)

What this comparison does not cover

We have not tested the components: this page compares what their vendors publish. It assesses neither design, accessibility nor performance. The cost of in-app messaging depends on the unit each vendor bills; see for example Knock or Novu? Has a piece of information changed? Report it.
